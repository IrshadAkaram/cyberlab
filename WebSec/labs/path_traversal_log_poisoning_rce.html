🔍 Technical Mechanics: Why Log Poisoning Leads To RCE

In PHP, when a file is loaded using functions like include(), require(), or include_once(), PHP does not require the file to have a .php extension. The PHP interpreter scans through the entire file line by line, outputting raw text as plaintext HTML until it encounters an opening PHP tag: <?php. Once that tag is found, everything inside is executed as executable PHP code on the server.

Because web servers like Apache and Nginx log client headers (such as User-Agent or Referer) directly into plain log files on disk (e.g. /var/log/apache2/access.log), an attacker who controls their User-Agent can write arbitrary PHP payloads into that log. By traversing to that log with LFI, the attacker achieves immediate Remote Code Execution.

❌ Vulnerable PHP File Inclusion (LFI)
// view.php — Dangerous dynamic file inclusion
<?php
  $page = $_GET['file'];

  // VULNERABLE: Direct inclusion of user input!
  // Allows ../../../../var/log/apache2/access.log
  include($page);
?>
✅ Secure Hardened Implementation
// view.php — Strict whitelist & sanitization
<?php
  $allowed_pages = [
    'home'    => 'pages/home.php',
    'contact' => 'pages/contact.php',
    'about'   => 'pages/about.php'
  ];

  $requested = $_GET['file'] ?? 'home';

  // SECURE: Whitelist mapping completely blocks
  // path traversal and arbitrary log inclusion
  if (array_key_exists($requested, $allowed_pages)) {
      include($allowed_pages[$requested]);
  } else {
      http_response_code(404);
      die("Page not found.");
  }
?>
