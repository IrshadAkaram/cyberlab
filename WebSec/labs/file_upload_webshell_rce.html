🔍 Technical Mechanics: How Webshell Uploads Yield Full System RCE

When an application allows users to upload files without rigorous server-side verification, attackers can upload server-side scripts (such as .php, .phtml, .jsp, or .asp). If the uploaded file is placed into a directory that is directly mapped to the web server's document root (e.g. /uploads/), the web server's PHP/CGI interpreter will execute the code whenever a web request requests that file.

A basic webshell containing <?php system($_GET['cmd']); ?> immediately hands full operating system command execution to anyone who requests /uploads/shell.php?cmd=whoami, completely bypassing authentication and network perimeters.

❌ Vulnerable PHP Upload Script
// upload.php — Flawed validation logic
<?php
  $filename = $_FILES['avatar']['name'];
  $temp = $_FILES['avatar']['tmp_name'];

  // FLAW 1: Blindly trusts client-supplied filename!
  // FLAW 2: Saves inside web-accessible directory!
  $destination = "uploads/" . $filename;

  move_uploaded_file($temp, $destination);
  echo "File uploaded to: " . $destination;
?>
✅ Hardened Secure Upload Implementation
// upload.php — Multi-layer defense
<?php
  // 1. Strict whitelist of allowed extensions
  $allowed_exts = ['jpg', 'jpeg', 'png'];
  $ext = strtolower(pathinfo($_FILES['avatar']['name'], PATHINFO_EXTENSION));
  if (!in_array($ext, $allowed_exts)) die("Invalid file type.");

  // 2. Verify magic bytes & re-encode image with GD
  $finfo = new finfo(FILEINFO_MIME_TYPE);
  $mime = $finfo->file($_FILES['avatar']['tmp_name']);
  if (!in_array($mime, ['image/jpeg', 'image/png'])) die("Fake image.");

  // 3. Rename to random UUID outside web root & disable exec
  $safe_name = bin2hex(random_bytes(16)) . "." . $ext;
  move_uploaded_file($_FILES['avatar']['tmp_name'], "/var/storage/" . $safe_name);
?>
