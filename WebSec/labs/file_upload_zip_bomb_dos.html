🔍 Technical Mechanics: Why Zip Bombs Cause Denial of Service

Compression algorithms like Deflate/DEFLATE64 compress repetitive data (such as repeated zeroes) with extreme efficiency. A malicious file can be constructed so that a tiny 42 KB compressed file decompresses into millions of gigabytes or petabytes of data.

Because standard file upload checks only evaluate the HTTP body size or compressed file size (e.g. $_FILES['zip']['size'] < 20MB), the zip bomb effortlessly sails through the upload gatekeeper. When the backend executes $zip->extractTo() without enforcing strict decompression limits, the server exhausts all disk blocks (No space left on device), consumes all RAM, triggers the kernel Out-Of-Memory (OOM) killer, and crashes all web and database services for all users.

❌ Vulnerable Naive Decompression
// extract.php — Unprotected archive extraction
<?php
  $zip = new ZipArchive();
  if ($zip->open($_FILES['archive']['tmp_name']) === TRUE) {
      // VULNERABLE: Extracts everything blindly without
      // checking total uncompressed size or ratio!
      $zip->extractTo('/var/www/uploads/extracted/');
      $zip->close();
  }
?>
✅ Protected Decompression Guard
// extract.php — Strict size and ratio validation
<?php
  $MAX_SIZE = 50 * 1024 * 1024; // Max 50 MB uncompressed
  $MAX_RATIO = 10;              // Max 10:1 compression ratio
  $MAX_FILES = 100;

  $zip = new ZipArchive();
  if ($zip->open($_FILES['archive']['tmp_name']) === TRUE) {
      $totalSize = 0;
      if ($zip->numFiles > $MAX_FILES) die("Too many files.");

      for ($i = 0; $i < $zip->numFiles; $i++) {
          $stat = $zip->statIndex($i);
          $totalSize += $stat['size'];
          // Abort before extracting if threshold exceeded!
          if ($totalSize > $MAX_SIZE) die("Zip bomb detected!");
      }
      $zip->extractTo('/var/www/uploads/extracted/');
      $zip->close();
  }
?>
