🔍 Technical Deep-Dive: Why Did This Attack Succeed?

1. Same-Origin Policy (SOP) Role

Browser allows cross-origin requests to be SENT (even carrying cookies), but by default SOP strictly prevents attacker JavaScript from reading the incoming JSON response.

2. The Fatal CORS Misconfiguration

The server dynamically echoed Access-Control-Allow-Origin: evil.com alongside Access-Control-Allow-Credentials: true. This explicitly instructed the browser to bypass SOP!

3. Real Impact: Full Data Exfiltration

Because the browser permitted JS read access, the attacker's script immediately harvested Vikram's ₹28.5L compensation details, AWS credentials, and M&A documents into the loot vault.

🛡️ Production-Grade Remediation (Node.js & Python Flask)

❌ VULNERABLE: Dynamic Reflection with Credentials

// Insecure Node.js / Express
app.use((req, res, next) => {
  // CRITICAL BUG: Reflects any client-supplied Origin
  res.header("Access-Control-Allow-Origin", req.headers.origin);
  res.header("Access-Control-Allow-Credentials", "true");
  next();
});

✅ SECURE: Immutable Allowlist Validation

// Secure Production Implementation
const ALLOWED_ORIGINS = new Set([
  'https://portal.apex-enterprise.internal',
  'https://admin.apex-enterprise.internal'
]);

app.use((req, res, next) => {
  const origin = req.headers.origin;
  if (ALLOWED_ORIGINS.has(origin)) {
    res.header("Access-Control-Allow-Origin", origin);
    res.header("Access-Control-Allow-Credentials", "true");
    res.header("Vary", "Origin");
  }
  // Untrusted origins receive NO CORS headers!
  next();
});
