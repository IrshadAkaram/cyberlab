🛡️ Technical Root Cause & Wrapper Hardening

Why stream wrappers like expect:// turn entity expansion into full remote code execution, and how to stop it.

❌ Vulnerable Backend (expect:// Protocol Enabled) PHP / SimpleXML 
// ❌ Fatal Flaw: PHP expect extension loaded & entities enabled
// php.ini: extension=expect.so
$xmlData = file_get_contents('php://input');

// 🚨 When an entity references <!ENTITY rce SYSTEM "expect://whoami">,
// the PHP XML parser passes the string directly to the expect wrapper,
// which invokes /bin/sh to execute the command and returns STDOUT into the DOM!
$doc = simplexml_load_string($xmlData, 'SimpleXMLElement', LIBXML_NOENT);

echo "<report_status>" . (string)$doc->content . "</report_status>";
✅ Secure Backend (Disable Entity Loader & Wrappers) PHP / Configuration 
// ✅ 1. Disable external entity loading globally
libxml_disable_entity_loader(true);

// ✅ 2. Forbid entity substitution flag (Omit LIBXML_NOENT)
$doc = simplexml_load_string($xmlData, 'SimpleXMLElement', 0);

// ✅ 3. Disable dangerous wrappers in php.ini / runtime:
// - Uninstall expect.so extension
// - Disallow arbitrary remote wrappers with stream_wrapper_unregister('expect')

// ✅ 4. Best Practice: Prefer JSON APIs over complex XML schemas
$data = json_decode($jsonPayload, true);
