🔍 Technical Mechanics: How Password Reset Poisoning Leads to Account Takeover

Many web frameworks and legacy applications dynamically construct the password reset URL in emails using the HTTP Host header sent by the client: "https://" + $_SERVER['HTTP_HOST'] + "/reset?token=" + $token.

An attacker can submit a password reset request for ANY user and substitute their own domain into the Host header (or X-Forwarded-Host). The victim receives a genuine email from the company, but the link points to the attacker's server. When the victim clicks the link, their unique, secret reset token is sent directly to the attacker in the HTTP referer or request query, allowing the attacker to reset the victim's password and achieve a total account takeover.

// auth.php — Flawed URL assembly
<?php
  $email = $_POST['email'];
  $token = bin2hex(random_bytes(16));
  save_token_to_db($email, $token);

  // VULNERABLE: Blindly trusts user-controlled Host header!
  $host = $_SERVER['HTTP_HOST'];
  $link = "https://" . $host . "/reset-password?token=" . $token;

  send_email($email, "Reset Password", "Click here: " . $link);
?>
✅ Secure Hardened Reset Implementation
// auth.php — Hardened configuration-based URL
<?php
  $email = $_POST['email'];
  $token = bin2hex(random_bytes(32));
  // Store SHA-256 hash of token, 15-min expiry
  save_hashed_token($email, hash('sha256', $token), time() + 900);

  // SECURE: Domain is strictly loaded from immutable server config!
  $base_url = getenv('APP_CANONICAL_DOMAIN'); // e.g. "https://auth.megacorp.com"
  $link = $base_url . "/reset-password?token=" . $token;
