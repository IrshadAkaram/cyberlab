Why Did This Attack Work? (The Intranet CSRF Pivot)

Even though the attacker's website is hosted out on the public internet, the HTTP request is executed by the victim's own web browser. Because the browser runs inside the user's home network, it has direct connectivity to private IP addresses (192.168.1.1, 10.0.0.1) that external attackers cannot reach directly. By combining predictable default gateway IPs, default credentials (admin:admin), and the absence of Anti-CSRF protection, the attacker alters critical router settings without ever touching the victim's physical device.

1. INTRANET PIVOTING

The victim's browser acts as a proxy bridge, relaying external internet commands into isolated internal LAN subnets.

2. PREDICTABLE HARDCODED PARAMS

Home router models typically share standard URLs (/setup.cgi, /apply.cgi) with fixed parameter names.

3. MISSING PNA & CSRF DEFENSES

The legacy router management daemon accepted state-changing requests without checking Origin headers or verifying CSRF tokens.

❌ Vulnerable: Legacy Embedded Gateway Daemon

// Router CGI accepts GET/POST directly!
void handle_setup_cgi(request_t *req) {
    char *dns1 = get_param(req, "primary_dns");
    if (dns1) {
        // Blindly overwrites resolv.conf!
        system("echo nameserver %s > /etc/resolv.conf", dns1);
    }
}

✅ Remediated: Anti-CSRF Token + Private Network Access

// 1. Enforce unique Anti-CSRF session token
// 2. Reject public-to-private cross-origin requests
void handle_setup_cgi(request_t *req) {
    if (!verify_csrf_token(req->session, req->csrf_token)) {
        send_error_403(req, "CSRF Token Missing");
        return;
    }
    // Block requests originating outside local LAN
    if (!is_local_origin(req->headers.origin)) {
        send_error_403(req, "Foreign Origin Denied");
        return;
    }
}
