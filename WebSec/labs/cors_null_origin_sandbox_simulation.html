🛡️ Architecture Remediation: Never Trust Origin "null"

Kayi developers local testing ya sandboxed environments ke liye Access-Control-Allow-Origin: null whitelist kar dete hain. "null" origin ko koi bhi web attacker sandboxed iframes ya data URIs ke through effortlessly forge kar sakta hai. null ko kabhi allowlist me add na karein.

❌ VULNERABLE: Allowing "null" Origin

// Insecure Node.js / Express Implementation
const allowedOrigins = ['https://app.company.com', 'null'];

app.use((req, res, next) => {
  const origin = req.headers.origin;
  // FATAL: Sandboxed iframes send origin 'null' and are trusted!
  if (allowedOrigins.includes(origin)) {
    res.header("Access-Control-Allow-Origin", origin);
    res.header("Access-Control-Allow-Credentials", "true");
  }
  next();
});

✅ SECURE: Explicit Strict FQDN Validation

// Secure Node.js / Express Implementation
const TRUSTED_DOMAINS = new Set([
  "https://app.company.com",
  "https://portal.company.com"
]);

app.use((req, res, next) => {
  const origin = req.headers.origin;
  // Strictly disallow 'null' and require known FQDN
  if (origin && origin !== "null" && TRUSTED_DOMAINS.has(origin)) {
    res.header("Access-Control-Allow-Origin", origin);
    res.header("Access-Control-Allow-Credentials", "true");
    res.header("Vary", "Origin");
  }
  next();
});
