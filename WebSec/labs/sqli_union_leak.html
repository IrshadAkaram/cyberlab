💀 DATABASE EXFILTRATION: CREDENTIALS LEAKED VIA UNION

Through UNION injection, customer credentials stored in the isolated 'users' table were seamlessly merged into the product catalog response.

RULE 1: COLUMN COUNT

The UNION operator requires both SELECT statements to return the exact same number of columns. Attackers use ORDER BY 1, 2, 3... to discover this count.

RULE 2: COMPATIBLE DATA TYPES

The column data types must be compatible with each other in positional order (e.g. text columns mapped to text, numbers to numbers).

RULE 3: RESPONSE HARVESTING

Once aligned, the attacker extracts password hashes, API keys, and internal records straight into the public HTTP response!

❌ Vulnerable: Dynamic String Concatenation

# Attacker injects UNION into query structure!
query = "SELECT id, name, price FROM products " \
        "WHERE category = '" + user_input + "'"
cursor.execute(query)

✅ Remediated: Parameterized Query

# Placeholder binds input strictly as literal string!
query = "SELECT id, name, price FROM products " \
        "WHERE category = %s"
cursor.execute(query, (user_input,))
