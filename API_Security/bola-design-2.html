Beginner Friendly High Severity OWASP API #1

Broken Object Level Authorization (BOLA)

Ek aisi vulnerability jahan API server request bhejne wale user ka object ownership verify nahi karta, jisse attacker kisi doosre user ka record access kar leta hai. A critical vulnerability where the API server fails to validate object ownership, allowing any authenticated user to manipulate IDs and access records belonging to other users.

1. Overview & Core Terms

BOLA modern APIs ka sabse common flaw hai. Jab bhi REST API me URL ke andar IDs (jaise /users/1002, /orders/854) hoti hain, toh developers sirf JWT authentication check karte hain par ye bhool jate hain ki kya User 1001 ko User 1002 ka data dekhne ki permission hai. BOLA is the premier threat across modern APIs. Because REST endpoints inherently expose identifiers in paths or bodies, developers often authenticate the token but neglect authorizing the user's specific ownership over the requested data record.

💡

Golden Rule Golden Rule

Authentication (AuthN) ka matlab hai "Tum kaun ho?". Authorization (AuthZ) ka matlab hai "Tumhe kya access karne ka haq hai?". BOLA me AuthN pass hota hai, AuthZ fail hota hai. Authentication establishes identity ("Who are you?"). Authorization enforces permissions ("What are you allowed to touch?"). In BOLA, authentication succeeds, but authorization fails.

3. 4 Real-World Attack Scenarios

💳 Scenario 1: Financial & Invoice Scraping
Critical

Fuzzing GET /invoices/9410 to 9500 to extract customer PII and purchase history.

🏢 Scenario 2: Multi-Tenant Tenant Hop
Critical

Modifying tenant_id=418 to 419 leaks a competitor company's private repository and API keys.

🔥 Scenario 3: State-Changing Account Takeover
Critical

Sending PUT /api/users/1002 with {"email": "hacker@evil.com"} overwrites the victim's email.

🧩 Scenario 4: Leaked UUID Exploitation
High

UUIDs leaked in public profiles or forum comments allow querying unprotected document endpoints.

4. Code Remediation

Hamesha query ko logged-in user context se bind karein (Scoped Database Queries): Always bind database queries to the authenticated session context:

❌ Vulnerable (FastAPI)
1doc = db.query(Document).filter(
2  Document.id == doc_id
3).first()
✅ Secure (Scoped)
1doc = db.query(Document).filter(
2  Document.id == doc_id,
3  Document.owner_id == current_user.id # 🔒
4).first()

5. Pentesting Checklist

1. Map all object identifier parameters

Check URL paths, query parameters, and JSON bodies.

2. Cross-token swapping with Burp Autorize

Configure User B token and browse as User A to detect 200 OKs.

3. Test HTTP Write Verbs (PUT, PATCH, DELETE)

Verify if state-changing verbs enforce ownership validation.

6. Confusing Questions

❓ Kya UUID use karne se BOLA solve ho jata hai?
Nahi! UUID guess karna mushkil karta hai par authorization enforce nahi karta. Agar UUID leak ho jaye toh attack possible hai.
❓ BOLA aur BFLA me kya fark hai?
BOLA: Same privilege level par doosre user ka object dekhna (Horizontal).
BFLA: Normal user ka admin function access karna (Vertical).
